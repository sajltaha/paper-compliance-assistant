# Contribution workflow

Every student uses their own GitHub account. Do not share credentials or impersonate another commit author.
The initial package was prepared with AI assistance. Each student must verify and explain their submitted work; commit history records contributions made through their account.

1. Create an actual YouTrack issue with owner, priority, deadline, expected output and acceptance criteria.
2. Create a branch such as ACTUAL-ID-requirements-review.
3. Read, validate and make a substantive correction or addition. Include the issue ID in the commit message.
4. Open a pull request with the problem, change, checks and task link.
5. The other team member reviews. Resolve comments and retain review history.
6. Merge reviewed work into main; update the actual task with the PR and decision.
7. Use prob-period-1 for the current form submission. The team authorized correcting its target after reviewed integration; the former target is preserved as prob-period-1-before-update. Review subsequent changes before another version update and record the exact source SHA.

Close tasks when their acceptance criteria are met and supporting links are recorded. Use actual YouTrack issue IDs. Record contribution dates, participant evidence, review decisions and test outcomes as they occurred.
