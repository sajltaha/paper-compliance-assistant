# 4 Existing system comparison

Four relevant systems are compared across the same eight criteria: Penelope.ai [D01], Paperpal Preflight [D02], SEA [S03] and the Liang et al. scientific-feedback pipeline [S01]. The last two are research systems rather than equivalent commercial products. This distinction is necessary when interpreting reproducibility and feature coverage.

| Criterion | Penelope | Paperpal Preflight | SEA | Scientific feedback pipeline |
| --- | --- | --- | --- | --- |
| Primary purpose | Journal technical compliance [D01] | Journal readiness and critique [D02] | Scientific review generation [S03] | Manuscript feedback [S01] |
| Configurable criteria | Journal-specific configuration documented | Partner-journal configuration documented | Review framework; arbitrary checklist not established | Paper feedback pipeline; editable checklist not established |
| Formal structure checks | Required sections and counts documented | Technical compliance documented | Not established in reviewed source | Not established in reviewed source |
| Semantic feedback | Scope limited to documented checks | AI critique advertised | Central capability | Central capability |
| Evidence transparency | Marked-up sections documented | Evidence-based recommendations advertised | Consistency analysis described | Generated feedback compared with reviewers |
| Input workflow | Publishing-platform integration | Manuscript upload | Research PDF/parser pipeline | Full-PDF feedback pipeline |
| Local reproducibility | Self-hosting not established | Self-hosting not established | Research code available | Research code available |
| Main limitation for this project | Not evidence of arbitrary author-defined conference rubrics | Partner settings differ from editable conference criteria | Fine-tuning/evaluation differs from compliance | User-perceived utility differs from per-criterion validity |

These are source-based comparisons, not hands-on tests. Not established means the reviewed source does not substantiate a capability; it does not prove that capability is absent. The proposed system should be justified by the local user need and evaluated implementation, not by unsupported negative claims about competitors. A promising design emphasis is an author-editable conference rubric with criterion-level provenance and explicit uncertainty.
