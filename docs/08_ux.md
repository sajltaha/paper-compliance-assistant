# 8 UX prototype

The standalone prototype demonstrates manuscript selection, requirements editing and confirmation, analysis progress, criterion-level results, evidence inspection, filtering and rechecking. A visible demo indicator explains that no PDF parsing or AI request takes place. The demonstration uses a synthetic manuscript so it can be shared without disclosing private research.

The key journey is upload or load a synthetic example, enter criteria, confirm criteria, inspect the mock results and open the evidence for a finding. Empty input and unsupported file types expose validation messages. Keyboard focus and status announcements are included. The future Vue application will replace the demonstration data with the documented REST contract.

| Scenario | Prototype representation | Implementation dependency |
| --- | --- | --- |
| First submission | File chooser, source notice, editable requirements and confirmation | Upload validation, parser and criterion API. |
| Explain a finding | Criterion status, explanation, source excerpt and recommendation | Validated result JSON and preserved anchors. |
| Uncertain or failed check | Insufficient-evidence example and error states | Parser confidence/unsupported features and provider failure handling. |
| Revise and recheck | Return to inputs and edit the synthetic scenario | Versioned documents and saved analysis history. |

The prototype is a UX artefact and does not establish usability or analysis quality. Usability validation is a later activity: ask target users to complete a task and record time, confusion and comments.
